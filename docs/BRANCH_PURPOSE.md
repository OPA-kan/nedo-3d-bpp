# このbranchは何のためにあり、quietguardはなぜ効いたのか

一次資料: 台帳の `preaction-*` / `quiet-guard-*` / `state_model_*` 各エントリ、
`HANDOFF.md`、`agent/agent.py` の該当ブロック。

---

## 1. branchの出自と、その問いの結末

branch名 `v5-hypothesis-validation` の v5 は、**distributional-fill
pre-action student v5** を指す。116特徴のラベル非依存な局所幾何モデルで、
「行動する前に、どちらの分岐が最終 fill を良くするか」を当てさせるもの。
このbranchはその**検出力付き確認**を回すために切られた。

**結果は棄却である**（`preaction-local-geometry-family-rejected-with-power`、
2026-08-16）。

* 厳密 cross-fit では強く見えた: 719/1053 対 657/1053、127勝65敗、
  p=9.05e-6、14/14 ストリームで非後退。
* 凍結した検出力ゲート（不一致ペアが37以上に達するまで符号検定を開封
  してはならない）が、最初の seed-60 コホートを**ラベルを開かずに**
  検出力不足と判定。
* 12ストリームに広げて42不一致で開封 → **161/229 対 157/229、23勝19敗、
  p=0.644、3ストリーム後退**。cross-fit の優位は新ストリームへ移らない。

つまり**branchは、その創設時の仮説が否定された後も続いている**。
以降は「学習したものが手組みランカーを超えられるか」というキャンペーン全体の
trunk として機能している。

## 2. 何を実現しようとしているのか

エージェントは**手組みの探索＋ランカー**である。賭けているのは、
**盤面状態上の学習された関数が、手調整スコアより良い配置を選べる**という
命題。placed がゲートかつ増幅器なので、placed が増えれば6成分すべてが動く
（`docs/SUBMISSION_HISTORY.md`）。

## 3. このbranchで試して閉じた学習線

| 線 | 何を学習させたか | 結末 |
|---|---|---|
| pre-action v5 | 局所幾何116特徴で分岐方向 | **検出力付きで棄却**（p=0.644） |
| pre-action v6 | スタンプ高さグリッド | 開発で棄却（26ストリーム非後退を満たす方策なし） |
| counterfactual afterstate value | 物理afterstateで fill 継続利得 | 確認runで再現失敗 |
| deviation trigger | 「ここで逸脱すべき」を決定時状態から | 表現律速。**4つの表現が pooled placed AUC 0.561 の壁を越えられず** |
| selfplay hazard | 物理なし世界で生存を学習 | 入口ゲート落ち（実枝で AUC 0.512 対 0.561） |
| safety reranker (Gate 2) | 安全モデルで候補を差し替え | **決定的に失敗**: 35 swaps、pooled placed **−37**、7勝13敗、topple+slide 10→11 |

**共通の形**: どれも「**学習に決定させる**」設計で、どれも落ちた。
特に safety reranker は示唆的で、安全性の知覚は正しかった（較正 AUC 0.933）
のに、**安全な配置は良い盤面手ではなかった**——差し替えが払った placed に
見合う安全すら買えていない。

## 4. quietguardが唯一効いた理由

quietguard は**学習に決定させない**。学習が決めるのは
「**いつ本物の物理を見に行くか**」と「**どの順で見るか**」だけで、
**決定は物理が下す**。

### 機構（`agent/agent.py`）

1. **トリガー**（学習）: 較正済み安全ロジット（Gate 1 のモデル、約129KBの
   JSONとして agent.py に埋め込み）が、方策が**既に選んだ**配置を採点する。
   1ステップ1回の前向き計算で約60μs。トリガー以上、またはモデル読み込み
   失敗なら**プローブせず素通り**——約70〜80%のステップは約0.3msで無変更。
2. **プローブ**（物理）: 危険と出た約20%のステップでのみ、in-process の
   PyBullet DIRECT クローンを作り、公式の力学（lateralFriction 0.8、
   rolling/spinning 0.01、restitution 0、angularDamping 0.8、soft は
   contactStiffness 5000 / damping 500、300ステップ settle、閾値 0.3m/30°）
   で**実際に試し置き**する。
3. **救済**（物理が裁定）: 現行候補が落ちると予測されたときだけ、代替を
   **ロジット降順**に（上限6プローブ / 1.5秒で）試し置きし、**物理が承認した
   最初の候補**を打つ。承認が無ければ現行候補のまま。**拒否はしない。**
4. **フェイルセーフ**: pybullet が無い / 重みが読めない場合、採用前の既定へ
   **ビット同一に退化**する。

### 測定

| 波 | 結果 |
|---|---|
| 開発（63話、5ゲート） | pooled placed 410 対 403、steps 431 対 424、6勝4敗、7構成すべて no-harm 床内。危険検出103回 → **物理承認救済9回** |
| 確認1（seed-20260817） | placed 210 対 184 |
| 確認2（seed-20260818、修正版） | placed 213 対 194、6勝2敗、物理死 6→5（**滑落が消滅**）、全ストリーム3配置床内。検出12回 → 救済10回 |

**3つの独立なストリーム集合・3つの独立な事前登録で placed が伸びた。**
これがキャンペーン初の出荷挙動変更になった。

### 公式での効き方（#5、35.375 → 35.195）

| 成分 | 差 | 読み |
|---|---:|---|
| cog | **+2.4%** | 物理品質は実際に上がった |
| stability | **+0.4%** | 同上 |
| fill | −1.2% | 対価 |
| placed | −1.6% | 対価 |
| **policy 最大時間** | **6.555 → 6.992 s（+0.44）** | **プローブが評価基盤で実際に走った時間署名** |

+0.44秒が重要で、フェイルセーフ退化なら 6.555 のままのはずである。
**ガードは評価基盤で確かに動いた。** 総合 −0.5% は提出間ノイズと同水準で、
deathband の −15.3% のような後退ではない。

**ローカルで一貫して placed を伸ばしたのに公式では中立**だった差は、
公式ケース混合ではガード配下の救済機会が薄いか、fill 系の代価が相殺して
いる可能性が高い（未確定）。

## 5. ここから読める設計原則

> **このbranchでは、学習に決定させる設計は6回すべて落ち、
> 学習を「いつ本物の物理を使うか」のトリガーに降格した設計だけが通った。**

理由の候補は safety reranker の失敗が言語化している——**一手の settle 安全性は
エピソード価値に変換されない**。安全な配置は往々にして悪い盤面手であり、
その代償は後で複利で効く。物理プローブが効くのは、それが「安全な手を選ぶ」
のではなく「**死ぬ手を避ける**」だけだからで、しかも避ける対象を
**物理そのものに判定させている**。

現在の未解決は `HANDOFF.md` の項目3〜5 と、6軸ラベルでの残余空間価値。
後者は本セッションで `build_branch_labels.py` の終端ベクトルを
placed/fill の2軸から6軸へ拡張したところまで。
