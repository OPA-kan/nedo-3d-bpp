## 4. ただしゲートだけでは placement と soft を説明できない

各成分が 0–100 のスケール(fill は `min(100*·, 100)` でクランプ、例示でも
soft が 100.0)で、ゲート通過率を f、通過時の条件付き平均を E[·|pass] と
すると、観測値 = f · E[·|pass] であり E ≤ 100 から

* stability から **f ≥ 20.72/100 = 0.207**

が出る。この下限を入れると

| 仮定 | E[place\|pass] ≤ | E[soft\|pass] ≤ | E[cog\|pass] ≤ | E[stab\|pass] ≤ |
| --- | ---: | ---: | ---: | ---: |
| f = 0.207 (下限) | 21.5 | 36.9 | 68.6 | 100.0 |
| f = 0.288 (stab が例示と同水準) | 15.5 | 26.6 | 49.5 | 72.1 |
| f = 0.434 (placed 率と一致) | 10.2 | 17.6 | 32.8 | 47.7 |

f をどう取っても、**ゲートを通った回だけを見ても placement と soft は
低い**。ゲート通過率が上がれば上がるほど、条件付きの値はむしろ悪くなる。
つまり placed を伸ばすことは必要だが、placement/soft の低さはそれとは
別に存在する。

`simulator/README.md:379` の配置スコア規則は物理を一切必要としない決定論的
幾何である:

* 優先手荷物 / ソフト貨物が**自分と異なる属性**の荷物に上から接触されて
  いれば減点(同属性同士の積み重ねは減点なし)
* 優先手荷物用コンテナがあるのに一般コンテナへ置いたら減点
* 優先とソフトは独立に評価

agent 側の現状は `agent/agent.py:3455-3464` の経路制約(優先荷物は優先
コンテナのみ)と `agent/agent.py:1367-1369` の支持面除外で、ソフト・優先の
上には**一切**候補を生成しない。後者は規則より厳しい — 規則は
ソフトの上のソフト、優先の上の優先を許すのに、それも捨てている。

1. **placement_score と soft_item_score をローカルで計算する。** 規則が

2. **cog_score をローカルで計算する。** 質量と位置から出る。定性定義のみ
   公開なので正規化は不明だが、単調な代理量としては使える。
3. **stability_score** は揺らしテストの手順が非公開で、最も高価。後回し。
4. placed(= ゲート通過)を伸ばす作業は依然として必要条件だが、それ「だけ」
