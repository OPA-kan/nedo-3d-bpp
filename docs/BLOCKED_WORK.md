## 0. すべての採否判断を止めている根本原因

同梱シミュレータの `evaluate()` は **6成分のうち2つ(fill, num_placed)しか
返さない**。残る4成分(cog / stability / placement / soft)はローカルで一度も
計算されない。したがって選択・順序・配分の変更は、その4成分に請求書が回っても
見えない。実例が death-band gate: placed +2.0 を根拠に出荷し、公式で総合
−15.3%(cog −20.7%, stability −22.4%)を請求された。

### ただし材料は既に揃っている

| 公式成分 | ローカルにある生の量 | 場所 |
|---|---|---|
| cog | `com_z`, `com_z_above_floor`, `com_height_ratio` | `diagnostics.py:540` |
| stability | shake 7指標 | `evaluator.py:205` + `diagnostics.py:463` |
| placement / soft | `priority_*` / `soft_*` の8指標 | `diagnostics.py:378` |
| fill / placed | 公式実装そのもの | `evaluator.py:81` |

**欠けているのは 0–100 への正規化だけ**である。そして正規化を推定する材料も
既にある: **公式フィードバックが4本**あり、いずれも6成分の内訳付きである
(`OFFICIAL_SCORE_LOG.md`)。

| 提出 | total | fill | cog | stab | place | soft | placed |

| submission22 | 17.581 | 29.276 | 14.224 | 20.721 | 4.45 | 7.65 | 0.434 |

### 外し方 — **2026-08-12 に第4点まで実施済み。交換レートは取れない**

`scripts/calibrate_proxies.py`。再構成可能な4提出(`trueenvelope` 35.375 /
`deathband` 29.959 / `3334` 相当 23.246 / `submission22` 17.581)を
4シナリオ・3反復で走らせ、
各シナリオ**内**で自前の対照(`base` + `base_null`)と比べた。結果:


全シナリオで完全に逆を向く代理は無いが、**「全代理の方向が合う」という3点
結論は撤回する。** 第4点により、placed・shake・属性coveringは読めるセルでも
partialになった。`fill` は全シナリオで untested のままである。

`reports/stowage/proxy-calibration.md`、生データは
`reports/stowage/calibration/`(388 KB、再実行可能)。

**残る制約:** 4点でも未公開の非線形スコア関数やゲートを同定できず、代理の
順序自体も構成依存である。したがって
`placed` を落として `priority_covered_by_other` を稼ぐような**成分間の取引は
依然として決着不能**である(実例: `reports/stowage/attr-guard-verdict.md`)。
第4点は追加済み(run `31568295912`)。次の校正課題は公式成分をもう1点増やす
ことではなく、fillの分解能改善か、同一公式構成を複数ローカルsceneで対応付ける
設計である。

## 直した計測器の欠陥(同じ轍を踏まないために)

- **フィンガープリントが6ノブを一度もハッシュしていなかった**。`DEATH_BAND_FALLBACK`
  (変数名ずれ)と `RELEASE_RISK_*` 5件(dataclass フィールド)。登録済みで
  未ハッシュ = マージがハッシュを動かさず変更できる状態。修正済み、未ハッシュ0
- **高さマップの落下高さでスコアを測ってはいけない**。`Ranker.score` の
  `−0.18·z·mass` は質量12kgで z の1cm誤差を0.1動かす。「支配的選択」の主張は
  この誤差を測っていた
- **計測が対象を乱す**。`policy()` と `env.step()` の間で候補を走査すると
  共有キャッシュを叩き、同一ケースが21手/転倒なし → 16手/転倒に変わる。
  記録と採点は2パスに分ける(`record_decisions.py` / `score_decisions.py`)
- **単発比較は読めない**。同一引数でも 35/36 とぶれ、腕間で 21〜37 に散る。
  `base_null` と反復なしの比較は全て無効

## 残った一本

致命手の盤面では **settled オラクルが0件**、release も全部限界ポーズだった。
選択でも探索でもないなら、**死はもっと前の配置で決まっている**。
`docs/ANCHOR_RECALL_ORACLE.md` の判定表で言えば
「failure step で oracle もゼロ → 残余空間価値・以前の配置選択」の枝で、
ここだけ誰も手をつけていない。

盤面価値の候補で唯一ステップ交絡を生き延びたのが `R_c`(残差 |AUC−0.5| ≈ 0.13)。
ただし**測り直しには同一ステップ内の対比が要る** — across-step は全て時計に
なる。それを作れるのは `scripts/measure_dead_end_branch.py` だけで、高価。

**この日の教訓が「安い代用品で測ると全部間違える」なので、次は高い方を使うこと。**

## 幾何として無傷で残っている観測(スコアに依存しない)

- 終了盤面で、空いていて荷物も入るポーズの **62.9%** が `transport_path_clear`
  だけで落ちる。到達不能は奥(y中央値 +0.250)、置けるのは扉側(−0.400)
