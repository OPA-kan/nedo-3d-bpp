## 各遷移で何を変えたか

### #0a → #0b（2026-08-01）: risk-on 化

変更: 回転リスク `λ_rot = 1.0`（力学モデル）+ 滑りリスク `λ_slide = 0.5`
+ packed-AABB キャッシュ。

結果: **placed 0.201 → 0.405 で積載数カットオフを跨いだ。** それまで
ゼロだった cog / stability / placement / soft が一斉に非ゼロ化。
これがカットオフゲートの直接観測であり、閾値が 0.201 と 0.405 の間に
あることが分かった唯一の証拠である。

注記: この提出には「差分不明の未コミット改変」が含まれていたと台帳が
明記しており、帰属はクリーンではない。

### #0b → #1 submission22（2026-08-02）: 17.581

構成（`SUBMISSION22_RECONSTRUCTION.md` による再構成）:
`ANCHOR_TRUE_ENVELOPE=0`（箱エンベロープ）、
`ANCHOR_FIRST_PASS_ATTEMPTS=64`、
`OFFLINE_DRY_RUN_ATTEMPTS_PER_ITEM=128`（Task A の有界dry run）。

この提出が「6成分中4成分にローカル信号が一つも無い」ことを初めて可視化した
（同梱評価器は fill と placed しか返さない）。ここから
`calculate_attribute_placement` と shake proxy の実装が始まる。

### #1 → #2 submission3334（2026-08-03）: +32.2%

変更: **第1パス深さ 64 → 256**（`ANCHOR_FIRST_PASS_ATTEMPTS`）と、
trunk 側の有界オフライン dry run。**2つ同時に入っているので単独帰属は
できない。**

結果: 6成分すべて上昇。placed +4.2% に対し**ゲート後ろ4成分が合計 +58.2%
＝約14倍の増幅**。これが増幅率の初測定。

副産物: それまで「深さ256は優先手荷物を下敷きにして placed を買っている
のでは」という懸念（ローカル priority_clean 0.803 → 0.575）が blocker
として置かれていたが、**公式 placement は倍以上に増えた**ので、その形の
懸念は棄却された。

### #2 → #3 trueenvelope（2026-08-03）: +52.2% — 最高スコア

変更: **アンカーエンベロープの y 軸の誤りを修正**（`22b88d2` cherry-pick、
`3b1635c`）。コンテナの実際の半空間から境界を導出する版に置き換え。

結果: 6成分すべて上昇し、3提出で総合がちょうど2倍。単一変更としては
キャンペーン最大の効果。

新知見: **増幅が減衰し始めた。** #1→#2 は placed +4.2% → 4成分 +58.2%
（約14倍）、#2→#3 は placed +11.6% → +77.6%（6.7倍）。カットオフを
下回るケースが減るほど、追加の placed は倍率を稼げなくなる。
**placed 一本槍の戦略には期限がある**ことがここで初めて見えた。

### #3 → #4 deathband（2026-08-04）: **−15.3%** — 唯一の明確な後退

変更: `DEATH_BAND_FALLBACK=1`。帰属はクリーンで、35.375 の成果物と提出
コミットの間で**デフォルト挙動を変えるノブはこれだけ**（tilt margin 0 は
恒等、L3 は両方オフ、構成順序も横這い）。

結果: 6成分すべて低下。placed −2.6% がゲート後ろ4成分で −20.0%、
**下向き 7.6倍**。上向きの 6.7倍と同水準で、**ゲート増幅は両方向に等しく
効く**ことが確定した。

帰結: 「placed を少し売って1配置あたりの質を買う」型の変更は、およそ7倍の
ハードルを越えねばならない。**採否はまず placed で判断する**という運用則の
根拠がこれ。

### #4 → #5 quietguard（2026-08-17）: 35.375 比 −0.5%

変更: `PHYSICS_PROBE_MODE=guard_quiet` を既定化（`d63bace`、dist SHA-256
`6ce23e70…`）。較正済み安全ロジットをトリガーに、危険と予測したときだけ
in-process PyBullet で試し置きし、物理が承認した候補に差し替える。
trueenvelope 以降のデフォルト差は**このガードのみ**なので、公式セット上の
実質的なペア比較になっている。

結果:

| 成分 | 差 | 読み |
|---|---:|---|
| cog | **+2.4%** | 物理品質は上がった |
| stability | **+0.4%** | 同上 |
| fill | −1.2% | その対価 |
| placed | −1.6% | その対価 |
| placement | −3.8% | |
| soft | **−7.7%** | 最大の後退 |
| policy 最大 | **+0.44 s**（6.555 → 6.992） | **ガードが評価基盤で実際に動いた署名** |

policy 時間の +0.44 s が重要で、フェイルセーフ退化（pybullet が無い等）
なら 6.555 のままのはずである。総合 −0.5% はタイミング依存探索の提出間
ノイズと同水準で、deathband のような後退ではない。

**当時の soft −7.7% の読み（ガードの差し替え先が属性被覆を悪化させた）は
2026-08-18 に撤回された。** placed を統制した残差は soft +0.20 で、
むしろトレンドの上にある。詳細は `docs/PROXY_SUPPORT.md` と台帳
`soft-regression-was-the-placed-drop-not-a-coverage-failure`。

## 通して読める構造

1. **placed はゲートかつ増幅器。** 跨ぐ前は4成分が literally 0（#0a）、
   跨いだ後も倍率が効く（14倍 → 6.7倍 → 下向き7.6倍）。
2. **その倍率は飽和しつつある。** 14倍 → 6.7倍への減衰は、カットオフ未満の
   ケースが減った signature。placed 一本槍は期限付き。
3. **時間は一度も効いていない。** optimization は全提出で 149〜150 s、
   policy は 6.52〜6.99 s。予算で買ったものは何も無い。
4. **status は5提出とも `Stopped in the middle`。** 全荷物を積み切った
   提出は一度も無く、終端はつねに失敗 action。
5. **単独変更で最大だったのは #3 のエンベロープ修正**（+52.2%）。
   これは新機能ではなく**幾何の誤りの修正**であり、キャンペーン最大の
   利得が「賢い探索」ではなく「バグ取り」から来ている。
6. **明確な後退は #4 だけ**（−15.3%）。#5 は −0.5% でノイズ域。

## 帰属が弱い箇所（誇張しないための注記）

- #0b は「差分不明の未コミット改変」を含む。
- #2 は第1パス深さと有界dry runが**同時に**入っており、単独帰属不能。
- #3・#4・#5 は帰属がクリーン（差分ノブが1つに特定されている）。
- 総合の重みは同定不能。0.05刻みの重みベクトル格子で 17.58143 を
  ±0.05 で再現するものが83通りあり、fill の重みは 0.00〜0.45 に広がる
  （`official-score-log-submission22`）。**重み推定を根拠にしてはならない。**
