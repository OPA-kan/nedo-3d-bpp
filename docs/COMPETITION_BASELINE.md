# NEDO Challenge 実戦ベースライン

## 競技契約

- オフライン最適化 `optimize`
  - 最大約80個の全荷物から順序を返す。
  - 制限時間は3分。最大150秒をドライラン駆動の局所探索へ使う。
  - 初期順序、オンライン共通配置コア、swap / Or-opt / 2荷物部分列マクロ探索の3段構成。
  - 配置個数、配置体積、充填率、安定性、低重心の順で評価する。
- オンライン最適化 `policy`
  - プール、現在のコンテナ状態から荷物・コンテナ・座標・姿勢を返す。
  - 制限時間は8秒。内部締切を6.5秒に設定する。
- シミュレーターは目標位置の8 cm上から荷物を落とす。
- 搬入経路は15 mm未満まで接近すると衝突扱いになる。

## A/B/Cモードの共通戦略

### A: オフライン計画あり、オンラインプール1

1. 体積・底面積・重量の複合スコアで構築的初期順序を作る。
2. ソフト荷物を後半へ送る。
3. 優先荷物を最後へ送り、取り出しやすさと下敷き回避を優先する。
4. オンラインと同じ配置コアで順序をドライランする。
5. 同じ荷物グループ内のswap / Or-optで順序を改善する。
6. 初回ドライランで成立した隣接2荷物を、逐次実行可能な部分列マクロ候補として保持する。
7. 部分列を一単位で移動する近傍も共通配置コアで先頭から再評価する。
8. 時間切れ前は必ずその時点の最良順序へ戻す。

### B: オフライン計画なし、プール3〜40

1. プールから最大10個を選び、8秒以内で候補探索する。
2. 硬い通常荷物、ソフト荷物、優先荷物の順に検討する。
3. 優先荷物は指定された優先コンテナだけへ送る。
4. 通常荷物は奥から、優先荷物は扉側から配置する。

### C: オフライン計画なし、プール1

- 到着順は変更せず、全姿勢・全コンテナから安全な候補を選ぶ。

## 現在の安全ルール

- 世界座標とコンテナローカル座標を明示的に変換する。
- 棚寸法は公式 `containers.py` の式から導出する。
- 境界面は公式5 mm＋settle位置ずれ10 mm＋丸め1 mmの合計16 mm内側へ置く。
- 横方向と搬入経路は、公式15 mmをfloat32化後も守るため内部では16 mm確保する。
- 搬入中は3次元AABB間のユークリッド最近接距離で16 mmを検査する。
- 既配置荷物はsettle後の観測クォータニオン `orn` から世界軸AABBを再構成し、落下後の傾きを後続搬入へ反映する。
- 内部候補は支持面への最終接触高さとする。
- 棚上の`place_pos`だけは公式直置き搬入の棚衝突を避けるため5.1 cm持ち上げる。
- 搬入開始高さは公式どおり、支持面から底面5 cm以内なら送信高さ、それ以外は送信高さ+8 cmを基本に天井でクリップする。
- 公式のY軸搬入→X軸横移動の2区間を両方検証する。
- 底面の55%以上が支持されない配置を拒否する。
- ソフト荷物と優先荷物を、後続荷物の支持面として使用しない。

## 次の改善候補

1. 安定性プロキシと実際の振動テストの相関を検証する。
2. 充填率と安定性の重みを比較実験する。
3. 4vCPU環境で1ドライラン時間と150秒内評価回数を計測する。
4. 共有プレフィックス状態キャッシュの効果を測る。
5. 2荷物マクロの採用率、再生失敗率、圧縮率、多様性損失を測る。
6. Bモードへ将来の配置不能を評価する後悔値を追加する。
7. settle後の境界ドリフト分布とPyBullet最近接距離の残差をログ化し、固定余白ではなく配置別ガードへ置き換える。
8. policy候補列挙を枝刈りし、ケース001の6.71秒を5秒未満へ戻す。
