# Self-Play Packing Game physical pilot

- Run: https://github.com/OPA-kan/nedo-3d-bpp/actions/runs/32472114418
- Commit: `db96f58`
- Scenario: `m-dual-preloaded-dedicated`, look-ahead 40
- Rules: minimum block 3, handoff probability 0.6, terminal reward 50,
  incremental soft/priority penalty 5

## Result

| Measure | rank-0 control | Top-K temperature |
|---|---:|---:|
| Games | 2 | 4 |
| Physical decisions | 36 | 72 |
| Unique physical states | 18 | 63 |
| Unique game states | 36 | 66 |
| Non-rank-0 actions | 0 | 31 |
| Handoffs | 10 | 20 |
| Selected physical failures | 0 | 0 |
| New soft/priority violations | 0 | 2 |
| Outcome-target-eligible games | 0 | 0 |

All games were exactly zero-sum and every completed block had length three or
four. Both arms reached the configured 18-step cap; none reached a true terminal
state. The two rank-0 games reproduced the same 18 physical boards, while the
exploration arm produced 63 unique physical boards from 72 decisions (87.5%).

## Verdict

**GO for Self-Play as a state-distribution generator.** Symmetric behavior
diversity substantially broadened the physical state distribution without
causing transport/containment/settling rejection and with a low incremental
attribute-violation rate (2/72 decisions).

**HOLD for value-network training.** The step cap produced no complete outcome
targets. The next gate must generate terminal games, then run bounded H3/H5
physical search on sampled game states to establish planning signal before any
game reward is treated as a useful production value target.

The measured candidate-generation cost is also material: two 18-step control
games required 9 minutes 41 seconds on the GitHub runner. MCTS must cache each
node's retained candidate set and separately budget proposal generation and
physics expansion.
