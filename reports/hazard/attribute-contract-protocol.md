# 属性契約を両側とも規則に合わせる

事前登録。波を投入する**前**に書いた（前回の attribute-support は順序を
逆にしたので、その反省を手順として実装している）。

## 仮説

台帳 `support-exhaustion-is-the-terminal-state` の記述がそのまま仮説である：

> **settled 経路は規則より厳しく、release 経路は規則より緩い。
> どちらの契約も公開規則に一致していない。**

この2つは別々に測定済みで、**互いの失敗要因を打ち消す関係**にある。

| 半分 | 直すもの | 測定済みの効果 | 測定済みの失敗要因 |
|---|---|---|---|
| `ATTRIBUTE_SUPPORT_RULE=1` | settled が厳しすぎる | 物理死 38.1% → **0.0%** | **違反率が上がる** |
| `RELEASE_ATTRIBUTE_GUARD=priority` | release が緩すぎる | 違反が全シナリオで**ゼロ** | **placed −11.5/シナリオ** |

支持則の失敗（違反増）は release ガードが消すもの。ガードの失敗（placed 減）
は支持則が合法体積として返すもの。**両者は一度も同時に試されていない。**

なぜ `priority` であって `all` ではないか: 実測した被覆60件は**すべて優先**
であり、soft はローカル clean 0.982 で取り除く違反が残っていない。台帳も
mode `priority` が mode `all` のコストの約1/3で済むと記録している。
**測定から導いた選択であり、調整可能な自由度ではない。**

なぜこれを狙うか: `reports/official/weights.md` により配置スコアの重みは
**0.26–0.31** と合計として同定され、値は 16.30 / 19.65 で他成分の1/3、
伸びしろは合算 **11.5–35.3点**。最大のプールである。

## アーム

4アームを**同一runでペア**に走らせる（時間予算探索なので負荷は対称に）。

* `base` — 出荷既定
* `attr_support_rule` — 支持則のみ（測定済み、再測でノイズ帯を共有させる）
* `attr_guard_priority` — release ガードのみ
* `attr_contract` — **両方**（本命）

7開発構成 × 4アーム × 3反復 = 84エピソード。3反復は
`baseline.json` の `paired_3v3_same_run` 床が前提としている本数。

## ゲート（凍結）

**A — 買うもの、主要ゲート。** `priority_covered_by_other` のプール値が
`base` 比で **50%以上減少**すること。50%という数字は発明ではない:
ガード単独が全シナリオで**ゼロ**にした実測があるので、これは保守側に置いた
バー。

**P — 払ってはいけないもの、失格ゲート。** どの構成でも
`baseline.json` の当該構成の `paired_3v3_same_run` 床を**負方向に**割らない
こと。1構成でも割れば、他が何であれ不採用。placed はゲート変数であり、
増幅は両方向に効く。

**S — 安定性。** プールした `shake_max_shift` と
`shake_peak_kinetic_energy` を placed と並べて報告し、悪化していれば
placed が伸びていても不採用（`AGENT_OPERATIONS.md` §5、HANDOFF 項目6）。
プールしたペアrunでのみ読む。

**N — 負の対照、同一wave内。** 組み合わせは両方の単独に勝たねばならない:
`attr_contract` の優先違反が `attr_support_rule` より**少なく**、かつ
`attr_contract` の placed が `attr_guard_priority` より**多い**こと。
どちらかが成り立たなければ、組み合わせの主張（互いの失敗要因を打ち消す）は
成立しておらず、Aが通っても不採用。

**確認波。** 開発を通っても採用ではない。未使用の順列・新シード・無調整で
同一ゲート（last-resort 先例）。

## 何も許諾しないこと

* 閾値は数字が出た後に動かさない。
* 公式スコアの改善を主張しない。違反数→0〜100 の写像は非公開であり、
  `ATTRIBUTE_PLACEMENT.md` は clean ratio をスコアとして提示することを
  禁じている。主張できるのは**ローカル違反数が減った**ことだけ。
* 失敗した場合、そのwaveで再調整しない。
