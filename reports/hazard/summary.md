# 終了ハザードモデル: 初めて step 内で識別できた信号

`scripts/fit_hazard_model.py`。既存 trace のみ(309 run / 6,293 決定 / 9 case)、
horizon 3、決定時点の17特徴、sklearn 不使用(出荷 agent に依存を足せないため)。

## 数字の読み方(順序が重要)

| 指標 | 値 | 意味 |
|---|---:|---|
| LOSO 平均 AUC | 0.945 | **引用禁止** |
| `step_index` 単独 AUC | **0.944** | 上の数字はほぼ全部これ=「終盤は終わりに近い」 |
| step 内 discordant-pair 精度 | **0.644** | 19,254 pairs、chance 0.5。**これが本体** |
| 同・step_index 除外 | 0.615 | 探索診断そのものに信号がある |

この作業系統でこれまで試した board value / Φ / MC rollout は、比較可能な
pair がゼロか chance 水準だった。step 内で 0.5 を超えたのは初めて。

## 使える範囲(構造的限界)

特徴は「その決定を生んだ**探索の状態**」(unit 被覆率、受理率、棄却プロファイル、
試行数)であって、**個別の候補ポーズではない**。したがって:

- **できない**: 同一盤面の候補間 tie-break(gate の swap 判定には使えない)
- **できる**: 状態レベルの危険度 → **gate の発火条件**として使う

現行 gate の発火条件は当てはめ定数 `DEATH_BAND_SCORE=-1.5`。ここを
LOSO 検証済みハザードに置き換えれば、§5.1 の自由係数が1つ消える。

測定した pair は「同 step・別軌跡」であって「同一盤面・別行動」ではない。
後者を測るには branch 解析側にこの特徴を持たせる必要がある(未実装)。
