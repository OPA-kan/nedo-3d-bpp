# Release安全性の予測則: 第1回層化replayデータからの同定結果

作成: 2026-07-30 / データ: `reports/replay-dataset/` の8 run(コミット済み)
再現: `python scripts/analyze_replay_dataset.py`(`reports/replay-analysis/latest.md` を再生成)

## データ

- ソース case 000 / 001 → Task B構成(optimize off, policy_timeout 8 s)
- pool (look_ahead) 20 / 40、`risk_gate=shadow`、`coverage=class_aware`、`mode=weighted`
- steps: 中盤〜終了直前(8, 12, 14, 16。エピソードが短い構成は 10, 11 / 14 に調整。
  b000-k40 は step 12 終了、b001-k20/k40 は step 16 未到達)
- 層: kind × gate(pass/reject)× score band(top1 / top10 / top10pct / tail)、
  per-stratum 8、選択候補は強制包含
- 合計 **679行**(release 462 / settled 217)。母集団率は全て
  `sampling_weight` でHorvitz-Thompson再重み付けした値を併記

## 確定した事実

1. **現行gateは高recall・低precision。** `not_placed_safe` に対し
   reject recall 0.93 / precision 0.42(重み付き)。rotation では recall 0.97。
   release候補の66%を棄却し、その棄却の約7割(重み付き)は実際には安全。
   これは enforce が飢餓を起こした理由(安全候補の大量誤棄却)と、
   off で release 転倒が残る理由(pass側にも6%の危険が残存 + そもそも
   gateが採用されていない)を同時に説明する。
2. **どの閾値も一様に不正確。** 棄却理由別のFP:TP比は support 186:72、
   com_margin 206:82、overhang 186:72、support_imbalance 60:29 と全理由で
   約2.5:1。「1本の閾値の置き場所が悪い」のではない。drop閾値は一度も
   発火していない。
3. **単変量で効くのはsupport幾何のみ、しかも弱い。** AUC(危険向き):
   support_ratio/overhang 0.64、com_margin 0.63。drop_normalized は 0.41 と
   逆向きに見えるが、これはsnapshot間交絡(危険な状況ほど低い位置に
   releaseする)であり、同一snapshot内contrastではdropの符号一貫性はない
   (8/13)。imbalance系は符号付きのままでは無情報(U字型)。
4. **rotation は既存Φの組合せで分離できる(→B)。** snapshot分割の
   ロジスティック(絶対値変換込み)で rotated_over_30 の test AUC **0.776**
   (単変量最良 0.624)。現在の実機失敗モード(settle中の約90°転倒)は
   この組合せモデルの守備範囲にある。
5. **hard-accept領域が存在する(→A的な部分)。** release候補のうち
   `support_ratio >= 0.6` は母集団の33%(重み付き)を占め、その中の
   rotated_over_30 は 0.4%(≥0.7 では観測0/92)。not_placed_safe も 3%弱。
   「ごく安全な領域」は support_ratio 単独で切り出せる。
6. **水平すべり(d_xy系)は既存Φでは分離できない(→C)。**
   not_placed_safe(すべり込み複合)の組合せtest AUC 0.656 は単変量最良
   0.696 を超えず、`support_ratio >= 0.7` でも重み付き 3〜6% のすべり残存。
   質量・摩擦・接触形状はΦに入っていない。
7. **rankingは安全性と整合していない。** release候補の score band 別
   not_placed_safe は top1 7.7% / top10 14.3% / top10pct 19.0% / tail 27.8%、
   rotated_over_30 は top1 でも 23.1%。現行スコアの上位選択は回転危険を
   避けない(evidence 6 の実機失敗と整合)。

## 分類の結論

\[
\boxed{\text{rotation: B(組合せで分離可)+ A的hard-accept領域あり / 水平すべり: C(既存Φ不足)}}
\]

- **A**(閾値の置き直しだけ)は不成立: 全閾値が同程度に不正確で、
  置き直しても pass/reject の質は精々単変量AUC 0.64 に律速される。
- **B** が rotation に成立: `P̂(rotated | Φ)` はロジスティックで作れる
  (解釈可能な重み: support_ratio と drop が負、imbalance系が正)。
- **C** は d_xy 系にのみ必要。候補は方向別CoM margin、接触形状、
  質量・摩擦(アイテム属性はsnapshotに既にある)、慣性モーメント。

## 次の一手(推奨)

1. rotation用の連続risk score `P̂(rotated_over_30 | Φ)` をロジスティックで
   確定し(データ追加生成→係数固定)、**risk-adjusted score**
   `Q_risk = Q_old − λ·P̂` としてshadow比較に載せる(全切断のenforceより
   機会損失を制御しやすい、当初計画どおりの第一候補)。
2. hard-acceptの補助則: `support_ratio >= 0.6` のrelease候補は
   risk項を実質0として扱ってよい(帯域の33%が回転リスクほぼゼロ)。
3. d_xy系を扱うかは別判断: まずアイテム属性(質量・摩擦・is_soft)を
   Φに合流させた再分析が安価(replayの再生成不要、stateから結合可能)。
   それでも分離しなければ新しい物理特徴の追加に進む。

## 注意

- 本レポートの率は第1回データ(679行、snapshot 16個)に基づく。
  snapshot数が少ないため、係数の確定には追加生成が必要。
- `not_valid` は全行 false: 搬送段階の衝突はこのデータでは観測されず、
  失敗は settle 段階に集中している(現行の問題設定と整合)。
- ロジスティックは分離可能性のprobeであり、本番のriskモデルの
  係数はこの値をそのまま使わないこと。
