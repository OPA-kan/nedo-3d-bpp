# Budgeted DAG search decision — run 32447121770

## Question

Can the 25 already executed H3/B3 physical DAGs test whether a search policy
can recover the best constrained root action while reading only part of each
graph?

## Contract

- Oracle: maximum reachable H3 `fill_score_proxy` under the full retained DAG.
- Physical hard constraints: `is_included`, `is_valid`, and `is_placed_safe`
  must all be true on every selected edge.
- Attribute hard constraints: priority/soft coverage or misrouting may not
  increase, including the recorded post-shake deltas.
- Rank-0 is the current hand-coded policy action.
- `prefix-v` sees only fill reached at the currently opened node.
- `oracle-v` is an exact-value upper control. It is not a trained or deployable
  model.
- One simulation opens at most one previously unread physical edge. Cached
  edges may be revisited without another physical read.

## Result

With physical plus attribute hard constraints, 19/25 graphs have at least two
root actions and at least one constrained H3-complete path. Six have no such
path; three of those six lose their last physical path only when the attribute
non-regression constraints are enabled.

| selector | constrained-oracle root recovery | mean physical edges read |
|---|---:|---:|
| current rank-0 | 14/19 (73.7%) | 0 |
| probe every B3 root once, choose best H1 fill | 18/19 (94.7%) | 2.89 |
| uniform PUCT, prefix value, 3 simulations, `c_puct=4` | 18/19 (94.7%) | 3.00 |
| best rank-prior PUCT, prefix value | 16/19 (84.2%) | 8.37 or more |
| rank-prior PUCT with oracle value, Q selection | 19/19 (100%) | 2.89 |

The H1 root scan and uniform PUCT miss the same graph:
`m-dual-shelf-mixed`, root step 12. There, rank-1/2 have higher immediate fill
(`11.5109` versus `11.2527`) but rank-0 reaches the better H3 fill
(`14.0683` versus `13.3265`). This is the only genuinely future-sensitive
root in the constrained 19-graph set.

The physical-only control has 22 eligible graphs. Rank-0 is oracle-optimal on
14/22, while the complete H1 root scan is oracle-optimal on 21/22. The same
single future-sensitive root remains.

## Decision

The local feedback loop is executable, but this corpus does not yet validate
MCTS as the source of improvement. Most apparent search gain comes from
physically probing all three root candidates once; deeper future value matters
on only 1/19 constrained graphs.

The existing rank prior is too sticky for a small-budget visit-count policy:
it preserves the one future-sensitive incumbent but misses several simple
root corrections. An exact value plus root-Q selection recovers every eligible
oracle, proving that the retained DAG contains enough information, but not that
the current learner can provide that value.

The next data collection should deliberately oversample roots where H1 ordering
and H3/H5 ordering disagree. Only that subset can distinguish learned future
value from a three-candidate physical root scan. Attribute-hard and
physical-only results should continue to be reported together because the
attribute hard constraint removes all H3-complete paths in 3/22 otherwise
physically solvable graphs.

This is retrospective offline evidence. No agent action, public submission, or
official-score claim was made.
